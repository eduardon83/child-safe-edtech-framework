# v0.6.0: Child-Safe EdTech Framework (CSEF)

The project is now called the **Child-Safe EdTech Framework (CSEF)**.

## Why

Swedish EdTech Industry pointed out that the project is a framework, not a standard. A formal standard is
adopted by a recognised standards body (CEN, CENELEC, ETSI, ISO) through a consensus process, and harmonised
standards can give a legal presumption of conformity. CSEF has neither. It is open guidance and tooling
that organisations choose to use. We agree, and the name and wording now say so.

CSEF aims to inform future formal standards and codes of conduct under the EU KIDS Act proposal. Any such
use needs validation by the competent official bodies.

## What changed

|---|---|
| Child-Safe EdTech Standard (CSES) | Child-Safe EdTech Framework (CSEF) |
| `eduardon83/child-safe-edtech-standards` | `eduardon83/child-safe-edtech-framework` |
| `standard/` | `framework/` |
| `cses.yaml` | `csef.yaml` |
| `cses-review` skill | `csef-review` skill |
| `cses-scan`, `cses-coc` | `csef-scan`, `csef-coc` |

| `cses-report/` | `csef-report/` |
| "Claiming conformance" | "Describing your results" (self-assessment) |

## Nothing breaks

- `cses.yaml` and `.cses/` manifests are still found. If both exist, `csef.yaml` wins.
- `cses-ignore:` comments still work, alongside `csef-ignore:`.
- `--standard-root` and `CSES_STANDARD_ROOT` still work, alongside `--framework-root` and `CSEF_FRAMEWORK_ROOT`.
- GitHub redirects the old repository URL, so `uses: eduardon83/child-safe-edtech-standards@v0.5.0` keeps
  working. New workflows should use `eduardon83/child-safe-edtech-framework@v0.6.0`.
- Rules and sources are unchanged: 106 rules, 50 sources.

## Upgrade

1. Rename `cses.yaml` to `csef.yaml` (optional).
2. Update the action reference in `.github/workflows/` to `eduardon83/child-safe-edtech-framework@v0.6.0`.
3. Replace the `cses-review` skill with `csef-review.zip` from this release.

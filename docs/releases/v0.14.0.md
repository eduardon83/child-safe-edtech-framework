# CSEF v0.14.0: learning data and the Workbench

Learning games can show where pupils get stuck and whether they learn. v0.14 shows how to log play so that makers
learn what works and teachers get real evidence, without breaking EU law. It also opens CSEF to people who do not
use a terminal: the Workbench runs every check that does not read code in the browser.

Guide: `framework/08-learning-data.md`, also online at https://csef.kendirstudios.pt/learning-data/

**Learning data**

- CSEF adopts the Open Game Data (OGD) event standard (Gagnon, Swanson and Harpstead 2024) as its reference format
  and adds the limits EU children need. OGD's "capture then analyze" becomes "declare, then capture", and public
  event-level data becomes group figures only.
- Four data tiers: operation data, event data, research extracts and open evidence. Only the last is public.
- A child-safe event profile, field by field (`framework/data/profile.yaml`): random player codes for one product,
  declared events and fields only, no free text, one device class, player metadata limited to the age band and
  settings in use.
- An open evidence feed, csef-evidence-0.1 (`framework/data/evidence-ontology.yaml`): time per unit, completion,
  stuck, help, learning gain, accessibility settings, natural stops, play mode and devices. One row per figure, so
  figures can be given for everyone and for each age band, country and period. At least 10 players and 3 classes
  behind every row, counts rounded to 5, periods to the month, no engagement metrics. Packaged as population.tsv,
  META.json, README.md and MANIFEST.json with SHA-256 hashes. The Play to Learn Toolkit reads the same layout with
  the same rules.
- `tooling/evidence.py`: `check-events` (an event file against the profile and the catalogue), `build-feed` and
  `check-feed`. A fictional sample (60 pupils in 6 classes) is in `examples/evidence-feed/`.
- Catalogues can read feeds as evidence. The Play to Learn Toolkit is the first: its Research pages show the
  figures per game and across games, labelled as the maker's data until someone independent checks the method.

**New rules**

| Rule | Level | |
|---|---|---|
| CORE-DAT-19 | MUST, 1 | Every logged event and field is in an event catalogue, with its purpose |
| CORE-DAT-20 | MUST, 1 | Player codes are random, one product only, never derived from identifiers |
| CORE-DAT-21 | MUST, 1 | No fingerprinting attributes in telemetry |
| CORE-DAT-22 | MUST, 2 | Inferences about a child stay at population level by default |
| CORE-DAT-23 | SHOULD, 2 | No engagement targets for children |
| CORE-DAT-24 | MUST, 1 | Open releases of learning data hold group figures only |
| CORE-DAT-25 | MUST, 1 | Research logging runs only in a study build |

B-DAT-01 adds the study build and "keys stay home": researchers never receive the link between player codes and
accounts (CJEU, EDPS v SRB). A `data_collection` block in csef.yaml drives five manifest checks; event names in code
are compared with the catalogue. Products that log nothing write `data_collection: {event_standard: none}`.

**Workbench** (https://csef.kendirstudios.pt/workbench/)

- For designers, decision makers and researchers. A form describes the product and writes csef.yaml; an editor
  shows the file for anything the form does not ask.
- Add documents (Word, PDF, Markdown, text, HTML, JSON, CSV) or a whole folder. Run the description check, the
  Literacy Compass, the serious-game pre-check, the label package, the code-of-conduct comparison, the event file
  check, the feed builder and the feed check. Download each report, or everything in one zip with csef.yaml.
- Runs in the browser with Pyodide. Files are never uploaded; there is no server, account or analytics.
  Organisations that block CDNs can host Pyodide and open the page with `?pyodide=`.
- `scan.py --description-only` and `tooling/workbench.py` give the same results on a computer. The description
  check lists the rules a developer still needs to check in code.

**Also**

- Guides can be published as website pages (`tooling/mdpage.py`); the Learning data guide is the first.
- Example reports for researchers on the site. The metadata export links a product's evidence feed.
- New sources: EDPB Guidelines 01/2025 on pseudonymisation, CJEU C-413/23 P (EDPS v SRB), EDPB Guidelines 2/2023
  on Art. 5(3) ePrivacy, the Digital Omnibus proposal COM(2025) 837 (watch list), Open Game Data (paper and
  event data standard).
- Rules: 124 to 131. Sources: 83 to 89, plus 9 in the Portugal pack.

**Help us test it**

We are looking for studios, associations, schools and researchers to try the Workbench and the learning data
tools on real products and tell us what is missing. Open an issue on GitHub, or write to the maintainers.

# v0.7.0: policy questionnaire

Every organisation can now set its child-safety boundaries by answering questions, and get the guardrails
and the documents to share in one go.

## How it works

```bash
pip install pyyaml python-docx
python3 tooling/policy.py --web     # or without --web, in the terminal
```

1. **Answer.** Who you are, what you build, for which ages, your minimum level, and for 31 practices
   (advertising, loot boxes, streaks, chat, AI companions, biometrics, data transfers and more): *Never*,
   *Only with approval* or *Follow our level*. Questions about features you do not use are skipped.
2. **Match.** Each answer is matched with the rules behind it: **Law** (required today), **Coming** (EU KIDS
   Act proposal, official guidelines) or **Recommended** (research). You see what goes beyond the law, what is
   allowed only with approval, and what is recommended but not adopted, with what it would take.
3. **Get the kit.**
   - `<id>.yaml`: your guardrails file for the scanner, the GitHub Action and the Claude skill
   - `boundaries-report` (.md, .html, .pdf, .docx): for management, DPO and legal counsel
   - `staff-policy` (.md, .html, .pdf, .docx): the policy in plain language for everyone
   - `agent-instructions.md`, `csef-check.yml`, `csef-review.zip`: for developers
   - `answers.json`: run again anytime; the version goes up and the report lists what changed

Answers can only make rules stricter. An approval never switches off a rule that applies at your level.
Everything runs locally; nothing is sent anywhere.

Example: `examples/policy/answers.json` (fictional).
